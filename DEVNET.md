## Proof it works

- **Relay now anchors via `evidence_anchor.anchor_hash`** (no longer a memo). The
  `POST /v1/anchor/solana` route writes `{hash, slot, timestamp}` to a PDA keyed
  by a **random, root-unlinkable nonce** — so the record CANNOT be recomputed from
  the evidence root alone (privacy: knowing the evidence doesn't reveal the
  anchor). The nonce is returned; Foren persists it and sends it back to keep a
  re-anchor **idempotent**. Verified on devnet: anchor with no nonce → random
  nonce + real tx; same root + that nonce → same PDA, empty signature (no
  duplicate spend); same root with no nonce → a *different* PDA (unlinkable).
- **Private export mode.** Foren can export a bundle that OMITS the exact Solana
  anchor (tx + record PDA), so the precise anchoring slot can't be read from the
  file. Because the nonce is random, the omitted record isn't re-derivable from
  the root; the Bitcoin OpenTimestamps proof (coarse) and any ZK slot-range proof
  carry the anchoring evidence instead. The full export remains the strongest
  (reads the exact on-chain record).
- **Verification reads on-chain program state.** Foren's `verifySolana` fetches the
  PDA account, checks the stored `hash` equals the bundle root **and** that the
  account is owned by the `evidence_anchor` program. Verified: matching root →
  `verified`; tampered root → `mismatch`; wrong program owner → `mismatch`.
- **ZK: real Groth16 proof verified on-chain.** The `evidence_zk` circuit
  (nullifier binding + slot range + location commitment) went through a
  single-contributor trusted setup; a proof was generated client-side and the VK
  initialised on `zk_verifier` (VK account
  `C9zHwZe6PtFbR58aovMkrawj6a4fMQaabxF113H5TVx5`). On devnet a **valid** proof was
  ACCEPTED (tx `4Npqh…`) and a **tampered** one REJECTED (`ProofInvalid`, on-chain
  pairing check ≠ 1). Reachable via the relay: `GET /v1/zk`, `POST /v1/zk/verify`.
  Re-run the full E2E: `cd circuits && node scripts/zk_e2e_devnet.mjs`.

## Toolchain (installed natively for arm64)

The pre-existing rust/solana toolchains were x86_64 and wouldn't run on this
Apple-Silicon Mac. Reinstalled native arm64 (all in user dirs, no sudo):
Rust 1.97.1, Solana/Agave CLI 4.2.1, `devnet-pow`. Add to PATH:

```bash
export PATH="$HOME/.local/share/solana/install/active_release/bin:$HOME/.cargo/bin:$PATH"
```

Rebuild + redeploy a program:

```bash
cargo build-sbf --manifest-path programs/evidence_anchor/Cargo.toml
solana program deploy target/deploy/evidence_anchor.so \
  --program-id target/deploy/evidence_anchor-keypair.json --url devnet
```

## Decisions still open (for the Foren-integration phase)

1. **Anchoring model — DONE (shared relay key).** The relay signs with one shared
   key and writes structured `evidence_anchor` PDA records (idempotent per root).
   Every record is owned by the relay signer. If you later want the per-user
   erasure property (owner = a client keypair, erasure = destroy the keypair), the
   browser must manage a funded key — a larger UX change, deferred.
2. **ZK prover placement.** The circuit, setup, prover, and on-chain verifier all
   work. Today proofs are generated by a Node script and relayed to chain via
   `POST /v1/zk/verify`. To make it a live user feature, run the prover **in the
   browser** (a Web Worker bundling `snarkjs` + the `evidence_zk.wasm`/`.zkey` so
   the private witness never leaves the device), then attach the proof + public
   inputs to the export bundle for anyone to verify. **This frontend wiring is the
   main remaining piece.**
3. **Mainnet.** Everything here is devnet. Mainnet needs real SOL (you fund; deploy
   is the same commands with `--url mainnet-beta`), the signer key moved to a
   secret manager, and a **production trusted-setup ceremony** for the circuit
   (the current single-contributor dev ceremony must not be used in production).
4. **Relay production build.** `relay/src/services/ipfs.ts` has a pre-existing
   `BodyInit` type error that fails `tsc` (dev via `tsx watch` is unaffected).
   Worth fixing before a `npm run build` deploy.
